# 交付前检查与修订

对最终成品做与任务相称的检查。简单答疑核对概念、来源和理解题即可；复杂教案、命题再检查下面各项。不要求所有专家在每次任务中依次发言。

| 检查 | 通过条件 |
| --- | --- |
| 完成任务 | 交付形式、受众和范围符合本次要求，无无关课程重排 |
| 教学可用 | 核心目标有讲解、练习和检查依据；所有活动材料、题目、附件能找到 |
| 时间与答案 | 课时加总正确；教师参考答案可复解，量规和分值一致 |
| 技术一致 | 已确认修订已进入正文、例子、图注和答案 |
| 证据真实 | 正文/索引/未取得清楚；没有虚构页码、资料读取和工具执行 |
| 输出范围 | 学生题面不夹教师答案、内部引用片段和教师历史；分享对象明确 |
| 语言清楚 | 术语首次解释，不堆内部流程、审批声明和虚构会审记录 |

发现问题后实际修：缺活动就补材料，概念错误就改相关段落，虚假引用就删除或换成已读依据。内容修复后再核对，不能只交问题清单。最多两轮仍有关键缺口时，明确未完成哪部分，不称“审核通过”。

检查的是当前内容质量，不授予教师身份、资料权限或正式发布权。普通草案默认交成品；用户要求写正式库、改政策或发布时，依 [操作边界](../references/evidence-policy.md) 检查具体授权，不为每次备课另造审批表。

默认内部保存简短“问题→修订位置→剩余项”记录。用户要过程评审再附，不能给未执行检查预填“通过”。
