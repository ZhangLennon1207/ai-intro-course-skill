# 教案、课堂活动与实验设计

输入：主题/单元、受众、时长、交付形式和课程证据。输出：教师能准备材料并实施的完整方案。按需读取 [教案模板](../templates/lesson-plan.md)、[PPT提纲](../templates/ppt-outline.md) 或 [实验模板](../templates/experiment-plan.md)，不要每次输出三种成品。

## 怎样完成一节课

1. 依据任务与正文选择本节核心学习问题。正式范围未核实时用一句话说明假设。用户只要求单元7的一节90分钟课，不能自行重排整个单元的线上课、实验和考核。
2. 将问题转成可以观察的学习目标，如“根据边表执行一轮搜索并说明节点选择依据”。每个核心目标都要有讲解或示范、学生练习、检查依据。
3. 先根据检索到的课程正文写知识讲解要点，再安排活动。技术术语准确，解释适合先备知识；专业案例用于理解课程目标，不用案例替代机制。
4. 排时间表，计入阅读、讲解、操作、讨论、汇报、讲评和转换时间，总和与用户时长一致。内容装不下就明确本节聚焦，不把其余内容擅自分给其他课程。
5. 将每个活动写完整：材料全文或明确图表、学生看到的原题、组织步骤和时间、应交内容、教师参考回答与评价依据。模拟数据标明自拟；真实材料给出出处。不能只有活动名字、空表和“教师自行准备”。
6. 课堂检查与作业给出题目、参考回答及判分要点，参考答案放在教师附件中。只有要求制作分发稿时才另行导出相应内容。
7. 写作时核对关键解释、示范步骤和答案，有错误即修正文与附件。只有用户要求专项核查或存在具体技术争议时才读取技术审校流程；不固定安排某些概念的额外核查。再执行 [质量检查](course-quality.md)。

## 实验与PPT

实验须有前提环境、输入数据、学生操作步骤、预期可观察结果、提交物和评价标准。平台版本与校内提交要求没取得就标具体待配置项；未运行的代码/平台操作不能写“已实测成功”。可给纸面或无账号替代，但说明其达成目标的范围。

PPT提纲写每页主张、呈现内容、讲解提示、活动/检查点、来源。只生成Markdown提纲时称提纲；用户要PPTX且当前环境支持，才制作实际文件，不把文本冒称PPT文件。

## 完成尺度

使用 [教学写法](../references/teaching-guidelines.md)。不要用十几张表或满篇逐字稿代替讲解内容。读者不需了解内部任务号、检索日志或角色切换。默认只交完整课堂方案；核对和修订体现在成品中。明确要求独立核查报告时才另交。
