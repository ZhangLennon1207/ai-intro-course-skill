# 单一课程Skill与原生专家安装

## 当前1.1.0

为支持WorkBuddy新建项目中的专家与技能选择，本版在唯一课程Skill外增加五份原生专家定义和快捷安装入口。教学逻辑继续保存在同一个课程Skill，七项工作流不拆成七个安装项。

原生专家定义位于 `.codebuddy/agents/`，全部绑定 `ai-intro-course`。`packaging/` 保存标准专家团清单、主管设置和头像；构建时按平台目录复制依赖，不维护第二套教学内容。旧原型的快捷提示和私有总库入口没有迁入本版。

新增 [使用者说明](user-guide.md) 和 [安装Agent说明](../bootstrap/ai-intro-course-setup/references/installation.md)。安装Agent优先注册平台真实资源并关联项目，管理能力不足时退到项目文件部署。文件部署、平台登记、项目绑定、选择器显示和实际运行分别核对，不混称完成。

已受派专家保持当前角色，不因加载共享Skill而再次成为主管；没有原生委派能力时仍能按顺序完成课程任务。普通备课继续只交成品，资料检索用于支撑内容。

## 1.0.0的单Skill收敛

更早的原型按教师专家插件与学生答疑插件分别交付。1.0.0收敛为同一课程Skill；下表描述当时的迁移，旧目录保持不动。

| 旧内容 | 新位置与处理 |
| --- | --- |
| 5个agents定义 | experts/内的普通角色说明；移除运行时注册字段 |
| 7个独立Skill | workflows/下的七份普通流程文档，只保留一个SKILL.md |
| 插件manifest、头像、主管默认设置 | 不迁移；单Skill不需要这些插件配置 |
| 教案、核查等模板 | templates/，按需读取；完善PPT和实验模板 |
| 学生独立包 | 同一个Skill的学生项目配置，实际数据隔离仍由平台完成 |
| 资料快照/固定序号 | 仅保留候选文件名作为搜索线索，不写死资料条数和执行口径 |
| 20个旧验收种子用例 | 保留主要任务意图，更新为当前资料/实际权限判断，所有WorkBuddy执行状态重新置为未执行 |

保留主管统筹、专业分工、证据优先、重要正式操作可审阅的思路。默认是同一助手的顺序视角处理，真实多Agent委派不是前置条件，也不能伪报独立会审。

此前教案中的主要体验问题已转成流程约束：附完整活动材料、来源简洁、修订合入正文、通过实际检索增强任务结果、不因身份元数据缺失给用户贴学生标签、不在普通草案附整套审批表。普通备课只交一份完整成品，不默认增加专项技术报告。

附件技术实施方案中关于GitHub、WorkBuddy、单Skill、师生项目和资料权限的架构已采用。四人分工及一周排期属于团队组织建议，未据此创建任务、邀请成员或修改远端平台。
