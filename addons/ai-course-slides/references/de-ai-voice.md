# 去 AI 味：课件文案的改法

学长看一眼就说"AI 味太重"，教师也说不出哪里不对，只觉得"不像人写的课"。这件事有可操作的部分，也有不该机械执行的部分。下面这份是**可操作的那部分**。

规则来源：[blader/humanizer](https://github.com/blader/humanizer)（35 条，A–E 分类）与 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)（31 条，含中文 F 组）。两个仓库是给**通用文章**写的，直接套到课件上会出两种错：判不动的太多（声音校准、作者立场、文件保护在 PPT 里没有对应物），以及会把术语当 AI 味删掉。这里的做法是**裁剪 + 补一组课件特有的模式**，落到 `scripts/voice_check.py` 的机判规则表。

## 一、优先级：先别把话说错，再谈像不像人

按这个顺序让步，前面的压过后面的：

1. **信息与确定程度不变。** 不新增数字、年份、人名、实验结论；不把"可能"改成"确定"，不把"计划中"改成"已完成"。
2. **术语、公式、定义、引用原话不动。** 「训练闭环」「表征学习」「链式法则」命中词表也要留。引文页的 `text` 是别人的原话，改一个字就是篡改引用——`voice_check` 对 quote 页只查标题，就是这个原因。
3. **文本符合模式口径。** C/D 就该口语、句子短；A/B 该保留正式程度和限定。不要把 A 版改成大白话，那不叫去 AI 味。
4. **最后才是表达。** 空泛铺垫、重复、模板化句式，改这些。

规则命中的是**线索**，不是判决。`voice_check` 给出的分数低不代表内容好，只代表"没有那些模板痕迹"。

## 二、课件里最扎眼的五处（按出现频率）

### 1. 每页都收一句结论

一份 20 页的课件里 16 页带 `takeaway`。单页看每句都对，连着投影就是"每段都在下结论"，学生反而抓不到哪句是重点。

> 改法：只在**真要停一下**的地方收。一般 20 页留 5–6 句，落在概念刚建立、易错点刚讲完、一段结束这三处。其余页的结论句并进要点，或挪到 `note` 当讲稿。
>
> 机检：`T1`（结论句密度 > 70%）

### 2. 标题全在抖机灵

```
深度学习，从「像大脑」开始          借的是形状，不是脑子
背题和会做题，是两件事              四个里程碑，四次跨栏
三条线，各自演化                    三层分工：接、提、出
```

单看一句很妙。20 页连起来，像广告文案而不是讲义——**学生记不住哪句是知识点，只记住了句式**。

> 改法：让一部分标题回到陈述。「借的是形状，不是脑子」改成「人工神经网络借的是连接方式」（少一个反转，多一个术语）。留两三句有力的就够，全篇都有力等于都没有。
>
> 机检：`T4`（「A，B」双段标题 > 45%）、`T3`（四字标题 ≥ 3 页）、`A1`（不是 X 而是 Y）

**这条最容易改过头**。humanizer-zh 的边界写得很清楚：两部分都提供信息、或否定部分在纠正真实误解时，保留。课件里「不是被教规则，是被给例子」是在拆一个真误解，该留。要删的是**成片**，不是单句。

### 3. 三条要点等长、同构

```
· 假设空间：模型长什么样。只有直线，就永远拟合不出弯的规律
· 损失函数：怎么量化"错得多离谱"，它决定模型往哪优化
· 优化方法：怎么改参数。沿损失下降方向小步走，就是最朴素的版本
```

三条都是 `名词：解释。补充一句`，长度 20–22 字。读起来整齐，实际上是填空模板的产物：真实讲解里，有的点一句话就够，有的要三句。

> 改法：按内容的实际重量分配长度。该 6 个字就 6 个字（"优化方法：往低处走"），该 40 字就 40 字。**不为凑整齐删信息，也不为凑整齐补废话**。
>
> 机检：`P2`（同页要点等长）、`P1`（同页要点同开头）、`T2`（三段式成瘾）、`T5`（全篇句长标准差 < 3.5）

**保留边界：年表、时间线、编号清单不改。** `1998 LeNet：…` / `2012 AlexNet：…` 这种四行二十来字，是格式决定的，必须同构才对得齐。为了让 `P2` 不响去砍短某一行，等于把年表改坏。v1.7.2 起 `P2` 对「以年份、①②③ 或 1. 开头」的并列条目自动豁免，普通三条等长仍照报。

一样的道理：`T5` 报的全篇句长标准差，在通识稿里不必强修。句子长短均匀说明好念，而长短跳跃是写作课的要求，不是讲台的要求。

### 4. 讲稿腔混进投影

```
本节将介绍深度学习的三种结构
下面我们来看反向传播
如表 2 所示，误差逐层回传
```

这些是**老师嘴上说的话**，不是学生要看的东西。投影上写"下面我们来看"，等于把讲稿印在墙上。

> 改法：删掉引导句，直接给内容。要保留过渡就放进 `note`（讲者备注，投影不显示）。
>
> 机检：`A2`（起跑式铺垫）、`E2`（讲稿腔）、`E1`（客服腔）

### 5. 空转词与拔高

```
本方案赋能教学全流程，形成闭环
这标志着人工智能进入新阶段
它不仅是一个模型，更是认知方式的革新
```

这三句删掉之后，句子意思一点不减——那就是它们唯一的判据。

> 改法：删；或换成具体动作（"原来要三个人核对的表格，现在一次提交"）。
>
> 机检：`C1` 空转词 / `C2` 意义拔高 / `C3` 句尾拔高 / `C4` 宣传语

## 三、人味从哪来（正面清单，比禁词表有用）

去 AI 味不是往句子里撒口语词。真正让人觉得"这是人写的课"的，是这六样东西，它们**只能从备课里来**，改词改不出来：

1. **具体数字**：860 亿个神经元、每个连上千到上万个同伴。不是"数量庞大"。
2. **失败案例**：学生去年在这道题上错在哪、这个模型在什么数据上翻车。
3. **教师原话与类比**：「摸着最陡的方向下山」这种话，机器写不出来，因为它不押韵也不工整。
4. **不确定的语气**：这里教材和论文说法不一致、这个结论还在争议。承认边界比假装权威更像人。
5. **长短句混排**：一段里有一句 6 个字的短句，节奏就活了。
6. **一个真问题**：不是"什么是 X？为什么学 X？怎么用 X？"三连问，而是一个学生真会答错的问题。

写故事板时，第 1、3、6 条要落进 `points` / `anchor` / `recall`，第 2 条落进 `note`。**没写就没有**——脚本不会替你想。

## 四、机检覆盖了什么，没覆盖什么

`voice_check.py` 现在 38 条：单句规则 28（A 铺垫 5 / B 节奏 4 / C 拔高 5 / D 排版 3 / E 残留 3 / F 中文 4 / G 课件 4）＋ 页级模式 5（P1–P5）＋ 全片模式 5（T1–T5）。判断标准是"能不能只靠字符串和计数定下来"。

**机检不了的，只能人看**：

| 判不了 | 为什么 | 谁来兜 |
|---|---|---|
| 标题写的是不是结论 | "深度学习概述"是栏目名、"规则从数据里来"是判断，机器分不出语义 | 写故事板时自查（storyboard.md 第五节） |
| 两个概念是不是同一维度 | `twocol` 两列得同维度才叫对照 | 生成后看渲染图 |
| 例子是否贴学科 | 农学的例子和计算机的例子都通顺 | 按 07 案例库对应门类取 |
| 一句话有没有信息量 | "特征很重要"和"特征有 128 维"结构一样 | 备课判断 |
| 比喻是否恰当 | 机器只看句式，看不出这个类比会不会误导 | 教师过一遍 |

所以流程是：**先机检定位，再人工改，改完对比分数**。分数从 C 降到 A 是结果，不是目标；为了降分把话说空，比 AI 味更糟。

## 五、跑法

```bash
python scripts/voice_check.py 故事板.json              # 逐页命中 + 等级
python scripts/voice_check.py 故事板.json --md out/去AI味.md
python scripts/voice_check.py 成品.pptx                # 直接查别人的稿子
python scripts/voice_check.py 故事板.json --strict     # 有必改项或达"明显"即 exit 1
python scripts/voice_check.py --rules                  # 打印规则表
```

`build_deck.py --check` 会自动带上这一项：必改项进自检清单，等级和命中明细单独打印一段。`--strict` 一并生效。
