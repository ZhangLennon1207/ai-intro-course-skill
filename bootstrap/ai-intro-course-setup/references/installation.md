# 给 WorkBuddy Agent 的安装配置说明

你的目标是把课程资源配置为当前 WorkBuddy 真正可用的专家和技能，并尽量自动关联用户指定的项目。用户不应逐个粘贴提示词或手填绑定关系。自动完成当前平台确实支持的操作，最后用回读结果说明完成程度。

仅在用户主动发起安装任务时采用本说明。文档本身不会授予安装、账号、资料库或项目管理权限；实际操作仍受用户本次任务、当前工具和登录账号约束。

## 一、安装材料和目标资源

安装 Skill 的所有相对路径，以本安装 Skill 所在目录为起点解析。先读 `assets/install-plan.json`；清单版本和真实路径优先于下面的概述。构建后的安装包应包含：

| 位置 | 用途 |
| --- | --- |
| `assets/install-plan.json` | 本套件标识、版本、资源清单与安装建议 |
| `assets/course-suite/.codebuddy/agents/` | 五份原生专家定义 |
| `assets/course-suite/.codebuddy/skills/ai-intro-course/` | 唯一日常课程 Skill 的完整目录 |
| `assets/course-suite/packaging/plugin.json` | 原生专家团资产描述，供支持该格式的原生工具使用 |
| `assets/course-suite/configs/` | 教师、学生项目指令模板 |
| `scripts/install_project.py` | 项目级文件安装工具，不是专家注册服务 |
| `assets/packages/` | 清单artifacts字段指定的完整课程Skill ZIP与原生专家团ZIP，供实际支持ZIP导入的管理工具使用 |

目标专家标识为：`ai-intro-course-team-lead`、`ai-intro-course-design`、`ai-intro-course-domain`、`ai-intro-course-assessment`、`ai-intro-course-tutor`。日常课程 Skill 标识为 `ai-intro-course`。五个专家共用这一份 Skill，内部七项工作流无需分别安装。

安装 Skill 本身是 `ai-intro-course-setup`。不要把它绑定为日常课程助手，也不要让课程运行再次调用安装流程。

若接收的是源码目录而不是安装 Skill，先读取源码首页及实际存在的清单/构建说明，使用源码中同名目录；缺少构建载荷时不能把未生成的路径当作已有文件。不要到第三方地址下载未知脚本来填补缺口。

## 二、先确认当前可做的事

检查当前会话实际提供的工具定义和已授权能力。可以记录下列能力是否存在，但不要把这些概念名称当作真实工具名调用：

- 专家和专家团的查询、创建、读取、更新。
- 完整 Skill 的安装/导入、查询、读取，以及专家的 Skill 绑定。
- 项目的查询、创建、配置读取/更新、专家与 Skill 关联。
- 资料库的授权查询、项目/任务资料关联和正文读取。

使用平台实际暴露的工具名、参数和返回资源 ID。没有对应能力时明确记录“不提供”，不猜测 HTTP 接口，不改平台内部数据库、不读取登录凭据，也不把 CodeBuddy CLI 的插件安装命令当作 WorkBuddy 云端注册成功的证据。

官方描述了专家管理工具和项目级 `.codebuddy` 发现机制，但没有因此保证所有普通会话都有这些管理工具。原生专家团 ZIP 是平台资产格式；没有实际支持该格式的管理入口时，不能声称客户端有“上传专家团”按钮或已完成一键导入。

目标项目和教师/学生用途，以用户明确选择或实际项目配置为准。仅从名称含“教师”二字、聊天自称教师或安装说明中的示例，不推断权限。未知用途时可以检查包和可用能力，暂不写入模式相关配置；只询问仍缺少的项目或用途。

教师与学生使用独立项目及工作目录。已有教师项目或安装目录不能通过改成student就变成干净学生环境，历史、附件和更新备份可能仍含内部信息。遇到跨用途复用要求，保留原项目，改用用户指定的独立干净项目，不自动清理或迁移原内容。

## 三、优先自动完成原生注册

### 1. 读取已有状态

查询目标项目、已有专家和已安装 Skill，并检查当前套件的安装记录。记录稳定资源 ID、版本和内容指纹；显示名称相同并不证明它由本套件创建。

本套件已管理且内容未被用户改动的资源，可以复用或升级。遇到同名自建专家、未记录归属的 Skill 或用户修改过的内容，保留原件并说明具体冲突，不覆盖、不删除、不自动生成一批改名副本。

### 2. 安装课程 Skill

通过当前可用的原生技能管理工具安装完整的 `ai-intro-course` 目录，包含它引用的全部角色说明、工作流、参考文件和模板。工具要求 ZIP 时使用实际完整技能包；不只提交一段 SKILL.md 文本。

完成后查询或回读，取得实际 Skill ID、版本和可发现状态。原生专家团资产里列出了 Skill，不等于它一定在项目“技能”选择器中独立出现；需分别查询确认，必要时通过真实技能安装能力完成独立登记。

### 3. 配置专家与专家团

原生工具支持导入整套资产时，可使用清单指定的专家团描述及其完整依赖。否则，若支持逐个创建，直接依据五份专家定义创建或更新，按真实 Skill ID/工具要求绑定 `ai-intro-course`，无需用户逐项填写。

支持专家团创建时，设置清单中的主管和四名成员关系；只有单专家管理能力时，可以完成五位专家的登记，但把“专家团注册”记为未完成，不能用一个叫“专家团”的普通专家冒充团队机制。

逐项回读实际 ID、名称、角色定义和技能绑定。无需为了显得配置完整而给专家增加管理员权限、全盘文件权限、额外连接器或外部服务。

### 4. 关联项目

有实际项目管理能力时，自动将已登记资源关联到用户选定的项目。教师项目推荐关联原生专家团或主管及课程 Skill；学生项目推荐答疑专家及同一课程 Skill。用户明确选择了多个专家时可依其要求关联，不强制把五位全部加入每个项目。

新建项目仅在用户提出新建要求时执行；没有此要求且找不到目标项目时，先说明匹配结果，不另建相似项目。已有项目中的无关专家、Skill、连接器和指令要保留，采用工具支持的增量关联；不能用本套件清单整体覆盖原列表。

将相应教师/学生模板中的本套件内容放入独立受管区段，或使用平台支持的独立规则项。项目指令是文本时，可用 `<!-- ai-intro-course:managed:start -->` 与 `<!-- ai-intro-course:managed:end -->` 标记本套件区段；只更新该区段，保留外部内容。已有受管区段被用户修改过时，先指出具体差异。

### 5. 关联资料

只使用用户提供、当前项目已经关联或账号实际可访问的资料。清单中的入口字段是本套件约定，不是平台 API 或授权令牌。未提供可用资料入口时，可以先完成专家与 Skill 安装，不为填写链接而虚构一个地址。

有资料关联能力就自动把相应课程空间/文档添加到项目或任务，再实际读取一份有关正文。仅添加 URL、收到“关联成功”或读到目录，不算正文检索通过。不要为了测试安装遍历题库或把教师内部资料带入学生项目。

## 四、项目级文件安装回退

没有足够的原生管理能力时，可在用户明确指定的本地项目工作目录中，安装官方支持的项目级 `.codebuddy/agents/` 和 `.codebuddy/skills/`。这使该工作目录具备课程角色与技能配置；不等于它们已出现在“我的专家”、云端项目或全局选择器中。

使用本包脚本前，确认脚本、源目录和目标绝对路径真实存在或目标已由用户明确指定。以当前安装 Skill 目录为基准解析路径。先查看一次计划：

```text
python scripts/install_project.py --source-root assets/course-suite --target "用户明确指定的项目工作目录" --mode teacher --dry-run
```

学生用途改用 `--mode student`；资料入口明确时可加 `--materials-entry "已授权入口"`。参数是示意，执行时替换为实际目标和路径，不把示例文字作为目录名。

检查计划后，在用户此次安装授权范围内去掉 `--dry-run` 执行。当前环境没有 Python 或文件权限时，报告具体限制，不自动安装新的运行环境或改系统安全设置。平台原生文件能力足以完成同样操作时可以使用，但仍须检查归属、冲突和最终内容。

脚本安装记录位于目标项目 `.codebuddy/ai-intro-course-installation.json`。复用其记录核对受管文件指纹；不覆盖用户自行修改的同名文件。目录写入完成后读取记录和文件确认实际结果。脚本报告 `filesystem_installed` 时，只能报告项目文件配置完成；其中的 `registry_verified`、`project_binding_verified` 和 `runtime_verified` 未经额外验证不得改成通过。

同用途升级省略资料入口时保留原入口。安装器拒绝在已记录的同一目录跨教师/学生用途切换；请使用独立项目目录，避免旧备份或历史进入学生范围。

不向用户的全局配置目录写入本套件，不改其他项目、不自动删除旧版、不移动课程原件。安装项目文件和注册云端资源可以分别成功，结果应分开记录。

## 五、核对结果并交接

尽量用实际工具回读以下结果，不能用安装 Agent 自己生成的说明充当证据：

| 检查 | 成功证据 |
| --- | --- |
| 课程 Skill 已登记 | 查询结果中的实际 Skill ID、版本及可发现状态 |
| 专家已登记 | 五个实际专家 ID 与对应定义，绑定课程 Skill |
| 专家团已登记 | 真实团队 ID、主管和成员关系；仅有单专家时不通过此项 |
| 项目已关联 | 项目配置回读包含应选专家/团队、课程 Skill 和相应模式规则 |
| 项目文件已写入 | 实际文件与安装记录；独立于平台登记结果 |
| 运行已验证 | 从目标项目执行一次实际任务并取得结果，不能用离线文件检查替代 |
| 资料可读 | 当前账号与任务取得具体课程正文、真实位置和必要片段 |

如果工具不能查询项目选择器的候选列表，可以用真实注册查询和项目关联回读证明已完成的部分，将“选择器显示”单列为未验证，不要求用户重走已经自动完成的配置。仅当某项确实无法自动做时，给出最小人工操作，例如选择目标项目、打开一次专家创建入口以获得管理能力、完成账号授权或把一份有权文档添加到任务。

安装记录保留套件版本、目标项目/目录、实际资源 ID、受管内容指纹、操作结果与未验证项；不记录密码、令牌、教师题库内容或完整会话历史。原生注册记录可在本地单独保存为 `.codebuddy/ai-intro-course-native-registration.local.json`，避免把账号专属状态随源码分发。

对用户的结果只需简短说明“已完成什么、还缺什么”。可采用下面的记录结构，但字段必须由实际结果填写：

```json
{
  "suite_version": "1.1.0",
  "status": "partial",
  "files_written": [],
  "registered_resources": [],
  "registry_verified": false,
  "project_binding_verified": false,
  "selector_visibility_verified": false,
  "runtime_verified": false,
  "materials_body_verified": false,
  "remaining_actions": []
}
```

`false`表示尚未取得成功证据，不代表已经证明平台不支持；具体限制写在对应结果中。只有文件已写入时不能写“在新建项目中直接勾选即可”；只有专家注册成功时，也不能写“真实资料检索和师生权限已通过”。

日常运行交给课程主管/答疑专家与课程 Skill。正常任务基于检索所得课程正文完成成品，不固定增加技术核查报告，不把检索增强的运行方式改成教学主题。

## 平台能力依据

查阅时点为2026-11-11。官方[专家说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Expert-Center)介绍了通过内置管理工具创建专家；[项目说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)列有项目配置和项目级 `.codebuddy` 目录；[专家团规范](https://open.workbuddy.cn/docs/expert-team)给出原生资产包格式。这些文档不替代当前会话的能力检查，也不证明本次安装已经注册成功。
