# 对话使用方法

在相应WorkBuddy项目内发任务。日常输入只需说清要什么；不用指定专家顺序或手填内部任务单。

| 目标 | 可以这样提问 | 应收到什么 |
| --- | --- | --- |
| 备课 | 结合课程资料，为经管/文法类学生设计单元7的90分钟课 | 一份完整教案、活动材料和教师参考回答，含必要来源 |
| 实验 | 按本项目第三章课件设计一节A*实验，不要求学生编程 | 完整输入、操作步骤、预期结果、提交与评价建议 |
| PPT | 将这份教案整理成15页PPT内容提纲 | 逐页主张、页面文案、活动与来源；未生成文件时不称PPTX |
| 组卷 | 根据已讲内容新编6题，分别给学生题面和教师答案 | 两份可区分的内容，参考解法、得分点和预计难度 |
| 答疑 | 我分不清g(n)和h(n)，用一个例子解释 | 直接解释和必要例子，可按要求补新自测解析 |

资料未成功关联时，可以把本人有权使用的具体文档添加到任务。Skill应说明缺少什么，而不是编造课件页码或把整个课程安排猜出来。

需要学生版时明确说“导出一份学生版，只含题面和公开材料”。有教师内部资料的对话不要直接分享给学生。需要正式修改或发布时说明目标文件和操作范围；默认备课仅交成品草案。

问题反馈记录：项目模式、安装版本、输入、实际输出、取得的来源及位置、具体哪里不符合预期。日志保存在当前受控范围；给GitHub提问题时用脱敏复现，不贴内部题目和学生身份信息。
