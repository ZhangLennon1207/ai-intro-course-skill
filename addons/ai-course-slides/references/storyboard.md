# 故事板结构与检查

故事板是实际PPTX的内容输入。先列本次需要讲的知识点，再逐页给主要观点、正文、出处和必要讲者备注。不要把大段教材拆成等长句子，也不为凑页数添加空泛总结。

```json
{
  "meta": {"course":"人工智能概论", "chapter":"本次主题", "mode":"B", "source":"实际取得的资料位置"},
  "coverage": ["知识点甲"],
  "slides": [
    {"type":"cover", "title":"本次要解决的问题"},
    {"type":"bullets", "title":"知识点甲的主要判断", "covers":["知识点甲"], "points":["可核对的解释","案例与边界"], "note":"来源与教师讲解提示"},
    {"type":"end", "title":"课后用一个任务检查理解"}
  ]
}
```

## 页面选择

`cover`封面，`section`过渡，`bullets`主要观点，`twocol`同维比较，`table`结构化数字或方案，`figure`实际本地图，`summary`收束，`quote`带真实来源的引用，`spine`主线，`recall`提问和答案，`end`结尾。类型应服务内容，不要求每份短课件全用一遍。

一页一个主要观点。信息过多先拆或精简，别依赖极小字体；公式解释符号和条件；图片注明示意/实测及来源。`takeaway`只有bullets和summary会绘制，不在其他页型填了就当投影已经出现。

## 覆盖与顺序

`coverage`列本次需要覆盖的内容，可用字符串或`{"key":"名称","alias":["别名"]}`；`covers`只写该页实际主讲的点，不把顺带提及当作完整覆盖。同一点跨两页可在两页声明。`spine`、`recall`等辅助页的`covers`可留空，避免扰乱主讲顺序。

`coverage_check.py`只检查声明与实际内容的可匹配程度。清单自身漏了知识点，覆盖率也可能很高；必须先对照真实大纲或本次任务确定清单。图像文字、同义改写和公式会影响机器匹配，疑似项应逐一核查，不直接判漏讲或捏造页码。

## 可选的主线与互动

需要主线时可写`memory.spine`、`memory.mnemonic`、`memory.anchors`与`memory.pitfalls`，并配一页spine；短课件可不加。不要为了有口诀造不准确或广告式表述。需要固定回问节奏时使用recall，问句、hint与answer分别填清楚。

生成器默认检查实际结构；不会因为没写口诀就拒绝两页补充材料。用户明确采用主线或互动规范时，可用`meta.require_memory=true`、`meta.require_recall=true`要求对应检查。`voice_check.py`的措辞结果默认供修订参考；仅显式设置`meta.enforce_voice=true`时纳入严格失败，不能据分数改变事实、术语或引用。

## 文件与图

图片填实际存在的本地路径，相对路径按故事板位置解析。找不到图就补齐或换页型，不交占位灰框。JSON、PPTX及渲染输出放教师项目的工作目录，原课件和模板只读，禁止用输出路径覆盖输入。
