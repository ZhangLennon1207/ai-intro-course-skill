# 人工智能概论课程 Skill

一个可导入 WorkBuddy 的课程 Skill，内含主管、教学设计、AI领域、出题评测和课程答疑五种角色，以及七项教学工作流。教师和学生安装同一个包，在各自项目的对话中使用；运行、资料检索和账号权限使用 WorkBuddy 原有能力。

本目录是供 GitHub 管理的源码候选，版本为1.0.0。它把先前 v1.1 专家插件方案迁移成单 Skill 产品，版本号属于新的产品形态，不表示旧包退版。发布与安装状态以仓库记录和 WorkBuddy 实机验收记录为准。

## 怎么开始

1. 将交付的 `ai-intro-course-1.0.0-workbuddy.zip` 在 WorkBuddy「专家·技能·连接器 → 技能 → 添加技能 → 上传技能」导入。
2. 分别建立教师项目和学生项目，关联同一个 Skill；按 [安装说明](docs/installation.md) 填入项目指令。
3. 将公开/学生资料与教师保密资料配置在不同受控空间，分别添加到对应项目/任务。
4. 在对话中直接提出备课或学习问题。首次测试可手动选中课程 Skill，确认能读取所需文件后再测试自然触发。

GitHub只保存技能规则、模板和模拟测试。题库、标准答案、内部材料、密钥以及含这些内容的任务产物不入仓库。真实资料入口由项目指令设置；课程负责人提供的既有链接保存在本地忽略文件中，未包含在可分发ZIP里。

## 文件架构

```text
ai-intro-course-skill/
├── .codebuddy/skills/ai-intro-course/
│   ├── SKILL.md                 唯一安装与任务入口
│   ├── experts/                 主管和四类专家的职责、输入输出
│   ├── workflows/               七项内部流程，均为普通Markdown
│   ├── references/              权限、证据定位和教学写法
│   └── templates/               教案、PPT、实验、题目、案例等模板
├── configs/                     教师/学生项目指令模板
├── docs/                        安装、访问、使用、迁移和验证说明
└── tests/                       20个WorkBuddy验收用例与空白执行记录
```

包内只有一个 `SKILL.md`。`experts`不是注册到运行平台的五个Agent，`workflows`不是七个额外安装包。默认由同一助手顺序完成必要视角的工作；只有实际可用且执行成功的原生委派才能报告为真实委派。

## 使用示例

- 教师：“结合课程资料，为经管和文法类学生设计单元7的90分钟课程。”
- 教师：“根据当前项目第三章课件设计A*实验，附学生材料与教师参考答案。”
- 学生：“解释A*为什么使用f(n)=g(n)+h(n)，并给我一道新编自测题和解析。”

专家通过WorkBuddy原生检索定位、阅读、补查课程资料，再据此生成内容。教案附完整活动材料，准确性融入写作与自检；默认只交用户要的成品，不附独立技术报告，简单答疑不轮流输出五个专家发言。
