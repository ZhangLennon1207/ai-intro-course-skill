# 解释深度与排版预设

A/B/C/D是生成器内部可选预设，不是让教师必答的身份或专业考试。先按当前任务、实际基础、时长与原件判断，不因专业名称自动删概念或推导。

| 预设 | 用途 | 排版倾向 |
| --- | --- | --- |
| A | 有原件，希望沿用结构和较完整解释 | 沿用原件语境，补充必要环节 |
| B | 从资料新制课件，需较完整技术解释 | 支持公式与关键推导 |
| C | 有原件，希望减少每页负担 | 较大字号、较少要点、补足直觉 |
| D | 新制通识课件，先建立概念直觉 | 低密度与可核对的案例 |

命令行可写 `--mode A|B|C|D`，或由故事板 `meta.mode` 指定；两者冲突应先核对。没有固定页数和统一课时要求，用户指定的时长、页数及内容范围优先。已有内容顺序、模板与符号优先保留；用户要求重构时给有用的差异说明，不机械要求原页一张不能删。

公式是否保留取决于教学目标及学生前置知识。降低深度应改变解释路径，不改正确结论；类比要说明限制。“激活函数让网络更聪明”不是非线性的有效解释，“神经网络像大脑一样思考”也不成立。推导保留改变结论的关键步骤，不堆无关公式。

脚本默认按预设调整字号和密度，不以专业标签禁用公式。确实需要按旧深度启发式检查时，可显式设置 `meta.enforce_depth_preset=true`；此检查只提示预设符合度，不证明课程内容适切。

案例优先用当前有权读取且已经核对的课程案例，也可按任务自拟并标明，不预设“07目录”等特定知识库必然存在。缺少某专业案例时说明并选择合理的自拟情境，不编造已查到的文件、页码或实验数据。
